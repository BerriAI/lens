# Rust worker contract ownership

The investigation worker now consumes the Rust types in `crates/contract` directly. Its compatibility export `litellm_lens::wire` still exists, with protocol version 7 and the same public type names. The Pydantic generator, `crates/lens/build.rs`, its typify dependencies and the runtime copy of `contract.json` are removed

The Rust schema export is byte-identical to the original 45-definition worker schema: SHA-256 `99fb11585be642193fce4796b6d53ac276d0ddec3462fbeec4dd0384209ee330`. The original remains an immutable test fixture. Model prompts obtain the schema from Rust, preserving constraints, defaults, enum ordering, nullable fields, tuple layout and required-field ordering. Object keys are sorted explicitly so enabling serde's `preserve_order` feature elsewhere in the workspace cannot change prompt schemas or generated artifacts

Before switching the worker, the old generated Rust implementation recorded 248 cases covering minimal and populated objects, extra-field errors and each omitted required field. The new types replay those cases without changing the expected outputs. Additional tests cover all 30 constrained string types at ASCII and Unicode boundaries, all 82 enum values, conversion paths and rejected enum values. The existing worker tests are unchanged

This preserves the old worker decoder, including its distinctions from schema validation. For example, serde accepts some omitted optional fields whose keys the schema requires, and numeric or collection constraints are enforced by the existing JSON-schema validation where they were before. Tightening those decoders during extraction would be a behavior change

`npm run generate:worker-contract` exports `schema/lens-worker.v7.json` and generates `src/ui/lib/src/lib/http/worker.d.ts`. Rust tests reject schema drift, and the `worker-ui-contract` CI job rejects TypeScript drift and type errors. The UI consumes the generated issue brief, in-flight, tool count and review-verdict types where their shapes match the current HTTP responses. Other API types remain on their existing contracts until their Rust route ports preserve the response defaults

The worker wire format is distinct from the public eval API. The concurrently merged eval contract owns `schema/lens.v1.json` and the Rust types in `contract::eval`. The SDK regenerates from that public schema without drift. Publishing the worker schema under that name would break the SDK, so protocol 7 is exported separately as `schema/lens-worker.v7.json`. The remaining public HTTP contracts and route implementations still need their Rust ports

This work began on Lens main at `76e3c74f28ae19667df52e76640198e1b5540432` and was reconciled with the eval-runs UI merge at `76fa69ab`, SDK fixes at `d04caacd`, and the public eval contract at `fd817339`. It closes the worker's dependency on Python-generated types, not the full Rust migration or the broader extraction. The remaining HTTP/domain ports, standalone provider flow, embedded LiteLLM integration, project-releaser, ops, charts, migration/recovery and full end-to-end qualification remain required

The [focused Rust run](evidence/rust-worker-contract-tests.log) passed 574 regular tests, including all unchanged worker tests; four live ClickHouse cases were normally ignored in that run. The [combined UI run](evidence/rust-worker-contract-ui-tests.log) passed 138 tests after reconciliation with the eval-runs UI. UI typechecking and generated TypeScript drift checks pass. The SDK's canonical eval schema also regenerates without drift using its locked generator `0.81.0` and Ruff `0.16.10`

[Mutation testing](evidence/rust-worker-contract-mutations.json) generated 52 mutations: 41 caught, eight unviable and three surviving, for a 93.2% kill rate among viable mutations. The survivors affect nullable-default cleanup that the current worker types do not emit, and a generic boolean default helper currently instantiated only with `true`. Cargo-mutants does not expand the string/enum macros; their conversion paths and boundaries have the explicit tests described above

The [full workspace run](evidence/rust-worker-contract-workspace.log) passed 1,964 regular tests after the SDK merge, with four normally ignored cases. Those [four live HTTP/ClickHouse cases](evidence/rust-worker-contract-live-traces.log) passed separately. The initial workspace attempt had one Docker `PortNotExposed` failure during fixture setup; the affected duplicate-insert test [passed in isolation](evidence/rust-worker-contract-clickhouse-retry.log), and the full retry used four test threads. [Workspace Clippy](evidence/rust-worker-contract-clippy.log), formatting, and the 58-route inventory ratchet pass. No production storage or deployment was changed

After the public eval contract landed, the [combined contract/worker run](evidence/rust-worker-contract-eval-reconcile.log) passed 605 regular tests and workspace Clippy passed again. The earlier full workspace total does not include these newly merged eval-contract tests. Worker mutation qualification covers the new worker-contract code, not the collaborator's eval module
